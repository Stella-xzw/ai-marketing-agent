系统选择器如何选主意图

排序因子规则说明
confidence_rankhigh=3, medium=2, low=1来自 LLM 候选输出，经系统一致性校验和必要降级后使用。
证据强度strong > medium > weak取候选引用的有效 evidence 中最高强度。
证据数量多 > 少仅统计能映射到该候选意图的 evidence。
业务优先级套餐 > 风险 > 拓客 > 关系 > 标讯 > 企业核验 > 低意图保证同一输入稳定可复现。
最近强证据minute 越大越近仅在双方都有强 evidence 且前序因子相同时使用。

策略池匹配原则

  • 策略节点只消费 selected_intent，不得直接消费 LLM 候选数组。
  • 策略只从固定 S1-S6 中匹配；F1/F2 是独立策略，不经过意图识别。
  • 同优先级策略同时进入规则校验，不按 strategy_id 二选一。
  • 同一策略多渠道或多触点按 strategy_binding_id 展开，不做笛卡尔积。
  • 最终是否触达由规则校验和承接系统执行结果决定。

固定策略池

策略适用意图渠道/触点优先级关键约束

状态、终止与异常分支

说明什么情况下不触达、终止链路、进入异常、频控、互斥或回放。

终止链路

已完成有效 VIP/SVIP 支付，或订单回补支付成功。

state_status=completedselected_intent=already_converted
  • 不调用 LLM
  • 不进入策略节点
  • 不提交通知

不触达

策略匹配不等于触达。全部任务被规则校验拦截，窗口级结果为 not_triggered。

frequency_limit_hitmutex_with_second_coupon
  • 保留策略和任务快照
  • 按任务粒度记录原因
  • 不切换到低优先级策略

成功触达

至少一条 notification_task 通过规则校验并进入通知提交。

strategy_trigger_status=triggeredexecution_status=success
  • 下发最小执行指令
  • 回执按 notification_task_id 归并
  • 写入回放记录

current_state

用途单用户首日链路最新状态。
关键字段first_android_event_time, current_window_type, state_status, expire_time。
终态completed / expired / failed。

tick_state

用途每次窗口判断的关键决策快照。
包含输入引用、摘要状态、主意图、选中策略、触达状态。
不包含曝光、点击、支付归因等效果事件。

notification_task_state

用途任务级规则校验、通知提交、执行回执。
粒度notification_task_id。
频控按任务状态和回放查询，不维护 recent_touch_history。

Agent 与业务系统交互

7.7 通知协议被压缩为最小执行指令和最小执行回执。

Agent 下发字段

字段是否必填说明
notification_task_id是通知任务 ID，用于幂等执行和回执归并。
user_id是目标用户。
strategy_id是S1-S6 / F1-F2。
strategy_binding_id是唯一表示策略、渠道和触点组合。

Agent 不下发窗口信息、意图信息、排序原因或大模型说明。承接系统通过 strategy_binding_id 读取模板、文案、权益、落地页或站内动作。

承接系统回执字段

字段是否必填说明
notification_task_id是用于归并对应任务。
execution_status是success / failed / ignored。
execution_fail_reason失败必填仅 failed 时必填。

回执不承载曝光、点击、关闭、到达、支付、投诉等效果事件。
